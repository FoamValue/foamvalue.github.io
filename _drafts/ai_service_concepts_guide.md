很多人第一次用 AI 服务时，会碰到一堆陌生术语：Token 是什么？Temperature 调多少合适？Context Window 又是干嘛的？

不懂这些概念，也能用 AI——就像不懂汽车原理也能开车。但如果你想"开得更好"——比如控制输出风格、节省费用、避免撞墙——了解这些概念是必要的。

这篇文章把 AI 服务中最核心的概念梳理一遍，不讲复杂的数学公式，用大白话讲清楚"是什么"和"怎么用"。

## Token：AI 的"字数"单位

### 是什么

Token 是 AI 模型处理文本的最小单位。它不是按"字"算的，而是按"词块"算的。

- 英文："Hello, how are you?" ≈ 4 个 Token（`Hello` `,` `how` `are` `you` `?` 拆成 4-5 块）
- 中文："你今天吃饭了吗" ≈ 4-5 个 Token（按词语切分）
- 一个汉字 ≈ 1-2 个 Token
- 一个英文单词 ≈ 1-2 个 Token

### 为什么重要

**AI 服务按 Token 计费**，不是按字数或字符数。你的输入（Prompt）和 AI 的输出（Response）都会消耗 Token。

### 使用技巧

- 日常对话：几十到几百 Token
- 长文档分析：几千到几万 Token
- 控制输出长度：通过 `max_tokens` 参数限制 AI 回复的最大 Token 数
- 节省费用：精简 Prompt 可以减少 Token 消耗

> 一个实用的估算：1000 个 Token ≈ 750 个英文单词 ≈ 500 个汉字。

## Context Window（上下文窗口）：AI 的"短时记忆"

### 是什么

Context Window 是 AI 模型一次能"记住"的最大 Token 数量。它决定了 AI 能同时处理多少信息。

- 小模型：4K-8K Token（约 3000-6000 字）
- 主流模型：8K-32K Token（约 6000-24000 字）
- 长上下文模型：100K-200K Token（约 7-15 万字）

### 为什么重要

Context Window 决定了你一次性能给 AI 多少"背景信息"：

- 一个 2 万字的项目文档，需要至少 32K 的 Context Window
- 分析一本 200 页的书，需要 100K 以上的模型
- 多轮对话中，早期聊天的内容会"滑出"窗口被遗忘

### 使用技巧

- **把最重要的信息放最后**：AI 对输入末尾的内容记忆更清晰（叫"近因效应"）
- **分段处理**：超长文档先让 AI 分段总结，再汇总
- **注意"窗口填满"**：当对话变长后，AI 会忘记前面的内容，必要时开启新对话

## Temperature：AI 的"创造力"旋钮

### 是什么

Temperature 控制 AI 输出的随机性，取值范围通常 0-2：

| 温度值 | 效果 | 适用场景 |
|--------|------|---------|
| 0 - 0.3 | 确定性强，每次输出几乎一样 | 代码生成、事实问答、数据提取 |
| 0.3 - 0.7 | 适度变化，保持合理 | 日常对话、文章写作、翻译 |
| 0.7 - 1.2 | 创意强，输出多样 | 头脑风暴、故事创作、广告文案 |
| > 1.2 | 高度随机，可能不靠谱 | 创意探索、诗歌生成 |

### 为什么重要

Temperature 是控制 AI "胆子"的参数：

- 低 Temperature：AI 只选最有可能的下一个词，输出保守、可预测
- 高 Temperature：AI 会选可能性较低的词，输出更有创意但也更不稳定

### 使用技巧

- **写代码用 0-0.2**：要精确，不允许"创意"
- **写文章用 0.5-0.7**：有变化但不离谱
- **头脑风暴用 0.8-1.0**：让 AI 跳出常规思维
- **不要超过 1.2**：超过这个值，输出质量明显下降

## Prompt：你怎么跟 AI 说话

### 是什么

Prompt 就是你给 AI 的输入文本。看似简单，但 Prompt 的质量直接影响输出质量。

### 好的 Prompt 长什么样

```
❌ 差："帮我写一篇文章"
✅ 好："帮我写一篇 800 字的中文科普文章，面向初中生，主题是'光合作用'，用比喻和例子解释，语气轻松活泼"
```

**好 Prompt 的四个要素：**

1. **角色设定**：告诉 AI 它扮演什么身份（"你是一名资深产品经理"）
2. **任务描述**：清晰说明要做什么（"分析以下 5 个功能的需求优先级"）
3. **输出格式**：指定输出的结构和样式（"用表格列出，每项附理由"）
4. **约束条件**：明确限制（"不超过 500 字，不要用专业术语"）

### 使用技巧

- **越具体越好**：多给例子、参考格式、具体要求
- **一次性给足上下文**：把完整的背景信息放在 Prompt 里
- **迭代优化**：先给一个简单 Prompt，根据输出结果逐步调整
- **使用"系统提示词"**：在支持的地方设置系统提示词，让 AI 保持一致的风格

## 模型：选对工具才能干好活

### 是什么

不同的 AI 模型擅长不同的任务。就像你不能用螺丝刀钉钉子，也不能用锤子拧螺丝。

### 常见模型分类

| 类型 | 代表模型 | 擅长 |
|------|---------|------|
| 通用对话 | Claude、GPT-4、Kimi | 日常问答、写作、分析 |
| 代码生成 | Claude Sonnet、GPT-4o | 编程、Debug、代码审查 |
| 轻量快速 | GPT-4o Mini、Claude Haiku | 简单任务、高并发、低成本 |
| 长文本 | Gemini 1.5 Pro、Claude | 超长文档分析、书籍解读 |
| 图片理解 | GPT-4o、Claude、Gemini | 图片分析、图表解读 |
| 图片生成 | DALL-E、Midjourney、Stable Diffusion | 创建图片 |

### 使用技巧

- **先想清楚任务类型**，再选模型
- **简单任务用轻量模型**：速度快、成本低，效果也不差
- **复杂任务用旗舰模型**：虽然贵，但准确性更高
- **同一家模型各有分工**：比如 Claude 3.5 Sonnet（代码强）、Claude 3.5 Haiku（速度快）

## 多轮对话 vs 单次调用

### 是什么

- **单次调用**：一次提问一次回答，互不关联
- **多轮对话**：连续提问，AI 记得前面的对话历史

### 什么时候用哪种

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 翻译一句话 | 单次调用 | 简单，不需要上下文 |
| 写一篇长文章 | 多轮对话 | 分步完善，逐步优化 |
| 分析代码 Bug | 多轮对话 | 先给代码，再给错误信息，再追问 |
| 批量处理数据 | 单次调用（API） | 高效，可并行 |

### 使用技巧

- 多轮对话中，如果话题变了，可以开新对话避免上下文污染
- 长对话中如果 AI "失忆"了，把关键信息再提一次
- API 调用时，手动管理对话历史（只保留最近几轮）可以节省 Token

## 总结

| 概念 | 一句话记 | 核心操作 |
|------|---------|---------|
| Token | AI 的"字数"单位，按它计费 | 精简 Prompt 省 Token |
| Context Window | AI 的短时记忆上限 | 重要信息放最后 |
| Temperature | 控制 AI 的创造力 | 精确任务用低值，创作用高值 |
| Prompt | 你怎么跟 AI 说话 | 角色+任务+格式+约束 |
| 模型 | 不同模型擅长不同事 | 按任务类型选模型 |
| 多轮对话 | AI 记得对话历史 | 保持上下文连贯 |

这些概念不需要一天记住。先用起来，遇到问题再回来看——**用多了自然就熟了**。
